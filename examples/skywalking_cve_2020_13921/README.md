# Worked example: Apache SkyWalking CVE-2020-13921 (CWE-89)

A real historical VCC repaired and validated end to end: the reported SQL
injection is reproduced on the vulnerable snapshot, a model repair is generated
and applied, the security regression passes, and the keyword-search feature is
preserved. The fix spans four JDBC query DAOs, so the repair is multi-file.

- Repository: `apache/skywalking`, vulnerable snapshot at fix parent `cc9ea271…`
- Weakness: search keyword / endpointName concatenated into SQL `LIKE` predicates
- Editable files (four DAOs): `H2AlarmQueryDAO`, `H2MetadataQueryDAO`,
  `H2TraceQueryDAO`, `MySQLAlarmQueryDAO`
- Security property: a crafted keyword cannot break out of the `LIKE` predicate
  (`SqlInjectionProbeTest`, exercising the real `H2AlarmQueryDAO` against in-memory H2)

## Files

| File | Purpose |
| --- | --- |
| `setup_scenario.py` | Rebuilds the prepared repository and writes `scenario.json` |
| `harness/` | Protected reproduction harness: fixture, functional test, injection probe, security adapter |
| `proposal.json` | The repair generated by Codex (`gpt-6-astra`) |
| `repair.patch` | The validated multi-file V → R patch |
| `expected_result.json` | The `validated` run report (evidence) |

## Run it

Needs JDK 8 and `mvn` on `PATH`. The first setup installs the upstream modules
to `~/.m2` (it needs Git submodules for that one reactor build); after that the
scenario builds the single module offline.

```bash
# 1. Build the prepared repository, scenario.json, and install upstream deps once.
python examples/skywalking_cve_2020_13921/setup_scenario.py /tmp/sw-cve --install

# 2a. Validate the reference repair without a model:
python src/repair_main.py /tmp/sw-cve/scenario.json --output /tmp/sw-cve/check \
  --proposal examples/skywalking_cve_2020_13921/proposal.json

# 2b. Or generate a repair with a model:
python src/repair_main.py /tmp/sw-cve/scenario.json --output /tmp/sw-cve/run \
  --provider codex --model gpt-6-astra --corpus data/splits/rag/repairs.jsonl
```

Expect `"status": "validated"`. The `revision` in `scenario.json` is the prepared
snapshot (fix parent plus the protected harness commit); the four DAOs are byte
for byte the vulnerable code at `cc9ea271`.

## Scope

This validates a V → R repair of the vulnerable snapshot against the configured
checks. It is not an independent proof that `cc9ea271` first introduced the
weakness, and it is not a P → R feature commit. The harness is a focused probe on
the alarm DAO, not a full functional suite for every query path.
